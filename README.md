## 场景

顾客要一杯**少糖**奶茶。甜度 3～5 算合格。

**做法一，店长写好的流程：**

```
倒茶 → 加 3 勺糖 → 尝一口 → 太甜就加奶 → 出杯
```

五步固定。甜了，是店长第 4 步写错了。

**做法二，店长只说「做好喝点」：**

```
店员加糖 → 店员尝一口 → 店员觉得太甜，加奶 → 店员出杯
```

店员自己决定「什么时候尝」「什么时候算好」。

## 差别只有一处

**「太甜就加奶」这个决定，是店长写进流程里的，还是店员当场做的？**

- 店长写进去 → **workflow**（控制流在代码里）
- 店员当场判断 → **agent**（控制流在模型里，店员脑子 = 大模型）

## 代码怎么读

只用了 4 个语法，够读了：

| 写法 | 人话 |
|---|---|
| `def 加糖(甜度):` | 定义一个新动作，叫「加糖」 |
| `return 甜度 + 6` | 这个动作交回的结果 |
| `甜度 = 加糖(甜度)` | 执行动作，结果存回「甜度」这个盒子 |
| `if 甜度 > 5:` | 如果太甜，就…… |

`for 第几步 in range(1, 9):` 就是「最多重复 8 次」。

## 自己改一下试试

1. 把做法一的 `if 甜度 > 5:` 整段删掉 → 它出杯时甜度是 6，**错的**。改代码的人负责。
2. 把 `店员的脑子()` 里 `if 甜度 > 5: return "加奶"` 删掉 → agent 也出错了。**模型的判断负责。**
3. 把 `range(1, 9)` 改成 `range(1, 2)` → 店员只做一步就被打断。这就是 agent 必须有的「刹车」。
