# 大肥鱼 · QQ 群机器人

一个用贴吧老哥语气说话的群友。三个阶段的能力，可以逐个开：

| 能力 | 开关 | 说明 |
|---|---|---|
| 被叫才回 | 一直开 | 流程写死，最稳 |
| 会用工具 | `USE_TOOLS=1` | 查天气、搜东西、查梗。这里开始变成 agent |
| 有记忆 | 跟着工具开 | 记住谁惹过它、谁是谁 |
| 自主插话 | `AUTO_CHANCE>0` | 自己判断要不要插嘴，默认关 |

## 骨架

```
收到群消息
  ├─ 存进上下文
  ├─ 是不是叫我？
  │    是 → 冷却检查 → 拼人设+画像+最近20条 → 模型（可能调工具）→ 回群
  │
  └─ 没叫我 → 概率+冷却+配额粗筛 → 模型判断"要不要插" → 插/不插
```

**粗筛在模型之前**（概率、冷却、每小时上限）。这是为了省钱——每条消息都问一遍模型，账单会很难看。

## 它会的五件事

| 工具 | 数据来源 | 触发时机 |
|---|---|---|
| `get_weather` | wttr.in | 问天气、穿什么 |
| `search_web` | 必应中国 | 问新闻、比分、需要核实的事 |
| `lookup_slang` | 必应（多查询打分） | 遇到不懂的梗 |
| `send_meme` | 本地图库 | 吐槽、装逼、破防的时候甩一张 |
| `remember` / `recall` | 本地 JSON | 有人骂它、夸它、说自己是干啥的 |

### 表情包：现搜现发

**默认不依赖图库。** 模型根据上下文自己编查询词，实时去必应图片搜一张发出去：

```
Q: 今天上班累成狗
    [工具] send_meme({'query': '累成狗 瘫倒'}) -> 现搜一张，119KB
A: 累就对了，说明你那点工资没白拿，就是拿得有点便宜。

Q: 你这也太离谱了吧
    [工具] send_meme({'query': '狗头 嘲讽'}) -> 现搜一张，574KB
```

耗时 0.2–2 秒，**发完即弃，服务器上不留任何图**。

三道关卡：

- **来源过滤**：书封/文档站（udocz、docin 等）直接拉黑；表情包站（奇兵、新浪图、昵图等）加权优先
- **尺寸过滤**：小于 6KB（图标）或大于 3MB（原图）丢弃
- **重试**：最多试 5 张，全失败就不发——只是少一张图，不影响回话

发图走 OneBot 的 base64 消息段，不依赖图床，不会裂图。

### 自动存进 QQ 收藏表情

发出去的每张表情包都会同时存进 QQ 的**收藏表情**（不是"收藏夹"，是表情面板那个）：

```
[工具] send_meme({'query': '嘲讽 狗头 鄙视'})
    -> 已发一张「嘲讽 狗头 鄙视」表情包（已存进 QQ 收藏表情）
实测：收藏表情 1 个 -> 2 个
```

实现方式：图片写到 NapCat 容器可见的共享目录（`napcat/cache/`），调 `add_custom_face` 存入，
**存完立刻删本地文件**，所以磁盘上仍然不留图。

群友说「这张收了」时，模型会调 `save_meme`——只存不发。

关闭：`.env` 里 `MEME_SAVE=0`。

> 另外 NapCat 还有个 `create_collection`（收藏夹），但它的 `picList` 写死为空，只能存文本，图片走不通。
> 图片要走的是上面这个「收藏表情」接口。

### 记忆

记忆存在 `data/memory.json`，结构：

```json
{"users": {"123456": {"nick": "老树", "items": [
  {"kind": "grudge", "what": "骂我傻狗", "when": "2026-11-05 18:00"}
]}}}
```

`kind` 三种：`grudge`（得罪过它）、`praise`（对它好）、`fact`（关于此人）。
下次这人说话，画像会自动拼进提示词。

## 自主插话怎么控

默认**开着**，四道闸：

```
群里 3 分钟内有 2 条以上消息（在聊吗？）
  → 每条消息 30% 概率被考虑
  → 同群 2 分钟冷却
  → 每小时最多 10 次
  → 模型最后再判断一次该不该插
```

实测三种情况：

| 场景 | 结果 |
|---|---|
| 只有 1 条新消息（冷清） | 不插话 |
| 5 条消息都在 3 分钟内（热闹） | 插话：「三年上市，三年后公司还在不在都难说」 |
| 消息都在 10 分钟前（荒废） | 不插话 |

模型还有否决权：正经排查技术问题时它会闭嘴，有人在吐槽时它才接话。

调节：

| 想要的效果 | 怎么改 `.env` |
|---|---|
| 更活跃 | `AUTO_CHANCE=0.6`、`AUTO_COOLDOWN=60` |
| 安静点 | `AUTO_CHANCE=0.1`、`AUTO_COOLDOWN=600` |
| 完全关掉 | `AUTO_CHANCE=0` |

## 部署到云服务器（7×24 在线）

### 0. 准备

- 一台 Linux 服务器（Ubuntu 22.04 以上，1 核 2G 够用）
- 装好 Docker 和 compose 插件

### 1. 上传代码

在 Mac 上执行：

```bash
rsync -av --exclude '.env' --exclude 'napcat' \
  qq-bot/ 用户名@服务器IP:/opt/dafeiyu/
```

（`.env` 里有你的 key，不进仓库也不走 rsync，稍后在服务器上直接填。）

### 2. 服务器上填 key

```bash
cd /opt/dafeiyu
cp .env.example .env      # 如果 rsync 没带 .env
nano .env                 # 填 OPENAI_API_KEY
```

### 3. 起服务

```bash
docker compose up -d --build
docker compose logs -f bot
```

两个容器：`napcat`（协议端）+ `dafeiyu-bot`（你的机器人）。

### 4. 扫码登录（第一次必须做）

协议端 WebUI 只监听服务器本机。在你 Mac 上开隧道：

```bash
ssh -L 6099:127.0.0.1:6099 用户名@服务器IP
```

保持这个终端不关，浏览器打开 http://127.0.0.1:6099 ，用**小号**扫码登录。

> 用大号的风险：第三方协议端违反腾讯用户协议，可能封号。你自己决定。

### 5. 确认 OneBot WebSocket

在 NapCat WebUI 里看网络配置，确认**正向 WebSocket** 已开启、端口 `3001`。
如果实际端口不同，改 `docker-compose.yml` 里 bot 的 `ONEBOT_WS`，然后 `docker compose up -d`。

### 6. 群里测试

拉它的小号进群，发 `@大肥鱼 在吗`。看日志：

```bash
docker compose logs -f bot
```

看到 `[收到]` 和 `[回复]` 就成了。

### 7. 安全

- `6099` 端口**不要**对公网开放，只走 SSH 隧道（compose 里已经只绑 127.0.0.1）
- 云服务器安全组只放 SSH
- `.env` 永不提交（已在 `.gitignore` 里）

## 调整行为

| 想改 | 改哪里 |
|---|---|
| 性格、口头禅 | `persona.py` |
| 什么时候回（@ / 关键词） | `bot.py` 的 `should_reply()` |
| 回得多快 | `.env` 的 `COOLDOWN` |
| 记得多少上下文 | `bot.py` 的 `MAX_HISTORY` |

## 什么时候才需要 agent

现在这套够用了。等你想加这些，才轮到 agent：

- 让它自己查天气、查梗、搜东西（**加工具**）
- 让它记住"上次谁惹过它"（**加记忆**）
- 让它看群气氛自己决定要不要插话（**加自主判断**，风险最高）

每加一样，反应变慢、变贵、更难预测。一次只加一样，加完观察一周。

## 常见问题

**连不上 NapCat？**
`docker compose logs -f napcat` 看协议端有没有起来；确认没有卡在扫码。

**重启后要重新扫码？**
挂载了 `./napcat/qq` 一般能保留登录态；如果重建了容器目录，可能要重扫。

**它不说话？**
检查三处：群消息里有没有 @ 到它的小号、`BOT_NAMES` 里的词对不对、`COOLDOWN` 是不是还没过。
